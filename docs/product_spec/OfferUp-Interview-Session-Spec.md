## 1. 模块边界

面试模块包含以下页面，反馈模块从用户点击「Open your feedback」后开始：

```
面试模块
  ├── 来电动画页        ← 进入面试的仪式感入口
  ├── 面试会话页        ← 核心沉浸式交互
  └── 结束过渡页        ← 面试收尾 + 等待反馈生成
        ↓ 用户点击「Open your feedback →」
反馈模块（独立）
```

---

## 2. 面试官角色系统

### 2.1 设计原则

面试官是有名字、有角色、有存在感的「人」，不是中性的 AI 系统。这个角色贯穿来电动画、面试会话、结束过渡页全程，建立一致的沉浸感。

### 2.2 角色名称映射

每次面试开始时，根据 `interviewer_agent` 和 `focus_type` 确定面试官身份：

| interviewer_agent | 默认名字 | 角色标题 |
|------------------|---------|---------|
| HR Agent | Sarah | HR Manager |
| Hiring Manager Agent | Marcus | Senior Product Manager / Engineering Manager（根据 JD 岗位类型） |
| 综合 Agent | Alex | Interviewer |

**有 JD 时：** 在角色标题后加公司名
```
Sarah · HR Manager · Personio
Marcus · Senior PM · Celonis
```

**无 JD（通用角色）时：** 只显示角色标题
```
Sarah · HR Manager
Marcus · Hiring Manager
```

### 2.3 头像设计

每个角色有固定的头像插画（不是照片，避免恐怖谷效应）。风格建议：简洁的线条头像，中性专业感，和产品整体 Editorial Warmth 风格一致。

MVP 阶段可以用字母 Avatar 替代（S / M / A），V2 再加插画头像。

## 3. 来电动画页

### 3.1 设计目标

建立「即将开始一次真实面试」的心理准备状态。不是花哨的动效，是有重量感的仪式入口。

### 3.2 页面内容

```
┌─────────────────────────────────────┐
│                                     │
│          [面试官头像 Avatar]          │
│                                     │
│         Sarah · HR Manager          │
│              Personio               │
│                                     │
│      Incoming interview call...     │
│       ⊙ ⊙ ⊙  （脉冲动画）            │
│                                     │
│   ┌─────────────────────────────┐   │
│   │      Accept call  →         │   │
│   └─────────────────────────────┘   │
│                                     │
│   Resume Deep Dive · ~15 minutes    │
│                                     │
└─────────────────────────────────────┘
```

**字段说明：**
- 面试官头像：Avatar（MVP 用字母，V2 用插画）
- 面试官名字 + 角色：来自角色系统
- 公司名：有 JD 时显示，无 JD 时不显示
- 「Incoming interview call...」：固定文案，脉冲动画
- Accept call 按钮：点击进入面试会话页
- 底部信息：题型 + 预估时长（来自设置配置）

### 3.3 背景与氛围

- 深色背景（和设置页的浅色背景形成切换感，像「进入了另一个空间」）
- 简洁，信息量极少，聚焦在「接不接这个电话」这一个决定上

## 4. 面试会话页

### 4.1 设计原则

**界面精简，聚焦对话。** 用户已知预计时长和题目数量（设置页告知），面试过程中不需要重复这些信息。只展示当前发生的事。

页面上同时存在的信息不超过四种：
1. 面试官是谁（顶部，轻量）
2. 当前问题（主区域，突出）
3. 用户的回答区域（主区域）
4. 题目进度（极轻，底部）

### 4.2 页面布局

```
┌─────────────────────────────────────────────┐
│  [S] Sarah · Personio          Q2 of 3  [✕] │  ← 顶栏（轻量）
├─────────────────────────────────────────────┤
│                                             │
│                                             │
│   ┌─────────────────────────────────────┐   │
│   │  [S] Sarah                          │   │
│   │                                     │   │
│   │  Walk me through your product       │   │  ← 面试官发言区
│   │  analytics project.                 │   │
│   │                                     │   │
│   │  ▶ 0:08  [播放音频按钮]             │   │  ← 面试官自然语音（如果可用）
│   └─────────────────────────────────────┘   │
│                                             │
│                                             │
│   ┌─────────────────────────────────────┐   │
│   │  Your answer                        │   │  ← 用户回答区
│   │                                     │   │
│   │  [按住说话] 或 [切换到文字输入]       │   │
│   └─────────────────────────────────────┘   │
│                                             │
└─────────────────────────────────────────────┘
```

### 4.3 顶栏

**左侧：** 面试官 Avatar（小）+ 名字 + 公司名（有时）
**中间：** `Q2 of 3`（题目进度，极小字，参考信息）
**右侧：** `✕` 退出按钮（点击有确认弹窗）

设计指导：顶栏是参考信息，不是主角。小字 + 次色，不抢焦点。

### 4.4 面试官发言区

**内容：**
- 面试官 Avatar + 名字（小）
- 问题文本（主体，较大字号）
- 语音播放控件（如果有高自然度面试官语音）

**交互：**
- 面试官提问时，文字从上方「打字机效果」出现；如果已接入高自然度面试官语音，可同步播放音频
- 用户可以随时点击语音播放控件重听
- 是追问时，在问题上方显示小标签「Follow-up」

**追问的视觉区分：**
追问出现时，面试官发言区不清空——保留主问题和之前的对话，追问以新的气泡追加在下方，像聊天记录一样向上滚动。这样用户能看到完整的对话上下文。

### 4.5 用户回答区

这是整个界面最重要的交互区域。

#### 语音输入模式（P1，需技术评估）

**方案 A：Push to Talk（按住说话）**

```
┌──────────────────────────────────────┐
│                                      │
│   ● 按住说话                          │  ← 默认状态，大按钮
│                                      │
└──────────────────────────────────────┘

按住时：
┌──────────────────────────────────────┐
│   ████████████  （波形动画）           │  ← 录音中状态
│   Recording... release to submit     │
└──────────────────────────────────────┘

松开后：
┌──────────────────────────────────────┐
│   Processing...                      │  ← Whisper 转写中（0.5-2s）
└──────────────────────────────────────┘

转写完成后：直接提交，进入 AI 追问判断
```

技术要求：MediaRecorder API + Whisper API
延迟：录音结束 → 提交：约 1-3 秒
体验：最接近真实面试，有「说话」的物理感

**方案 B：自动检测（VAD，语音活动检测）**

```
用户开始说话 → 自动开始录音（页面有提示）
用户停顿 1.5 秒 → 自动结束录音 → Whisper 转写 → 直接提交
```

技术要求：需要 VAD 库（如 @ricky0123/vad-web）
延迟：停顿后约 1.5s + Whisper 处理时间
体验：更自然，但可能误触（停顿思考时提前提交）

**技术评估建议：**

| 维度 | Push to Talk | 自动检测 VAD |
|------|-------------|-------------|
| 实现难度 | 低（原生 API） | 中（需要 VAD 库） |
| 误触风险 | 无 | 有（思考停顿） |
| 适合场景 | 桌面端 | 移动端更自然 |
| 用户感知 | 有操作感 | 更流畅 |
| MVP 推荐 | ✅ 优先 | P1 可加 |

**MVP 阶段推荐 Push to Talk**，原因：实现简单、误触风险低、「按住说话」的操作本身有仪式感，类似对讲机，反而强化了「面试中」的心理状态。

#### 文字输入模式（P0，兜底方案）

语音不可用时（浏览器不支持 / 用户拒绝麦克风权限），自动切换到文字输入：

```
┌──────────────────────────────────────┐
│  Type your answer here...            │
│                                      │
│                                      │
└──────────────────────────────────────┘
               [Submit →]
```

**语音 / 文字切换：**
右下角提供切换按钮，用户可以随时在两种模式之间切换，不打断面试流程。

#### 转写文字的处理

转写完成后**直接提交**，不需要确认步骤。

但转写结果会短暂显示（约 1 秒）让用户看到「系统听到了什么」：

```
┌──────────────────────────────────────┐
│  ✓ "I led the initiative to build   │  ← 转写结果，淡出
│     a dashboard because..."         │
└──────────────────────────────────────┘
```

这不是确认步骤，只是一个视觉回执——让用户知道系统理解了他的回答。1 秒后淡出，进入 AI 处理状态。

### 4.6 AI 处理状态

用户提交回答后，等待 AI 追问判断（约 0.5-1 秒）：

```
[S]  Sarah is thinking...  （轻量的点点动画）
```

- 如果触发追问：Sarah 的追问以新气泡出现；如果已接入高自然度面试官语音，可同步播放音频
- 如果不追问：进入下一题，或触发结束流程

### 4.7 结束触发

**触发 A：自然结束**
第 3 题的追问判断返回 false，AI 播报结束语：
```
"Thank you — that covers everything I wanted to ask.
Your feedback will be ready shortly."
```
然后自动跳转结束过渡页。

**触发 B：用户主动退出**
点击顶栏 `✕` 按钮：
```
弹窗：
「End this session?
  Your answers so far will still be evaluated.」

[Cancel]  [End session]
```
确认后跳转结束过渡页。

## 5. 结束过渡页

### 5.1 设计目标

这是面试模块的情感收尾，也是反馈模块的入口。

用户此刻的心理状态：有点累，有点不确定，期待知道结果。

这个页面需要做到：
- **认可**：这次练习是有价值的，已经认真完成了
- **郑重**：反馈是被认真准备的，不是随机生成的
- **期待，不焦虑**：像收到一封信，知道里面有认真写的内容，但还没打开

### 5.2 情感基调

**「信封」隐喻：** 反馈是一封被认真写好的信，用户选择自己打开它。

不是「你做得很好！」的即时反馈。  
不是「正在加载...」的技术等待。  
是「我们已经仔细听了你说的一切，正在为你整理」的郑重感。

### 5.3 页面内容与状态机

页面有两个状态：**生成中** 和 **准备好了**。

**状态一：生成中（用户进入后立即显示）**

```
┌─────────────────────────────────────────┐
│                                         │
│                                         │
│         [信封 / 抽象视觉元素]             │
│                                         │
│      That's a wrap.                     │  ← 大字，有重量感
│                                         │
│      Sarah has finished the session     │
│      and is putting together            │
│      your feedback.                     │  ← 面试官名字，郑重感
│                                         │
│      ····  （极轻的点动画）               │  ← 生成中状态
│                                         │
│                                         │
└─────────────────────────────────────────┘
```

**状态二：准备好了（反馈生成完成，轮询到 feedback_status=ready）**

```
┌─────────────────────────────────────────┐
│                                         │
│                                         │
│         [信封视觉，微动效果]              │
│                                         │
│      Your feedback is ready.            │  ← 替换掉「That's a wrap」
│                                         │
│      Sarah has reviewed your answers    │
│      and left her notes.                │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │    Open your feedback  →        │   │  ← 出现，有轻微入场动画
│   └─────────────────────────────────┘   │
│                                         │
│   3 questions · Resume Deep Dive        │  ← 小字，本次面试的摘要信息
│                                         │
└─────────────────────────────────────────┘
```

### 5.4 状态切换逻辑

```javascript
// 进入过渡页后立即开始轮询
const pollFeedbackStatus = async () => {
  const res = await fetch(`/api/session/${sessionId}/feedback-status`);
  const { feedback_status } = await res.json();
  
  if (feedback_status === 'ready') {
    // 切换到状态二，显示「Open your feedback」按钮
    setIsReady(true);
  } else if (feedback_status === 'failed') {
    // 显示错误状态和重试按钮
    setHasFailed(true);
  } else {
    // 继续轮询，2 秒一次
    setTimeout(pollFeedbackStatus, 2000);
  }
};
```

**错误状态：**
```
Something went wrong generating your feedback.
Your answers have been saved.

[Try again]  [Go to dashboard]
```

### 5.5 视觉设计指导

**背景：** 深色或极深的暖灰（和面试页一致，形成连续感），与反馈页的浅色背景形成切换——用户点击「Open your feedback」后，像从一个暗室走进一个明亮的空间。

**「信封」视觉元素：** 不需要是字面意义的信封插画。可以是一个抽象的几何形状，加上轻微的光晕或阴影，暗示「里面有东西」的感觉。MVP 阶段可以只用文案和极简动画，不依赖复杂插画。

**字体：** 大字用 Serif（和反馈页 Interview Feedback 标题一致），传递重量感和郑重感。

**动画：** 极克制。生成中用三个点的脉冲，不用旋转加载圈。按钮出现时有轻微的 fade + translate 入场，不用弹跳。

**「Open your feedback →」按钮：** 这是页面上唯一的主操作，视觉权重应该是整个页面最高的，但不是高饱和度的突兀颜色——用深色实边框按钮（和整体风格一致）。

## 5.5 会话恢复（成本最小方案）

用户关闭浏览器后重新进入，检测到有 `status = 'in_progress'` 的 session 时，在进入设置页前显示恢复提示：

```
┌─────────────────────────────────────────┐
│  You have an unfinished session         │
│  Resume Deep Dive · Started 2 hours ago │
│                                         │
│  [Continue]   [Start new session]       │
└─────────────────────────────────────────┘
```

**Continue：** 跳转 `/session/[id]/interview`，前端从数据库读取已有 exchanges，恢复到上次中断的题目位置。

**Start new session：** 旧 session `status` 更新为 `'abandoned'`，进入正常设置流程。

不做自动恢复，不提示已回答几题，不做复杂状态同步。

## 6. 技术规格

### 6.1 面试官语音

**产品决策：不要使用机械感 TTS 凑数。**

面试官声音是沉浸感的一部分。如果声音听起来机械、廉价或像浏览器默认朗读，会破坏真实面试感。

因此 MVP 规则是：

- 用户侧语音输入可以作为 P1：Push to Talk + Whisper 转写。
- 面试官侧不使用 Browser Speech Synthesis。
- 如果面试官要出声，必须使用更自然的高质量 voice model 或预生成自然语音。
- 如果高自然度面试官语音来不及实现，则 MVP 先只展示文字问题，不播放机械音频。

**可接受方案：高自然度预生成 + 播放**

问题生成完成后（Step 2），为每道主问题生成高自然度音频，存入 Supabase Storage。

面试过程中直接播放预生成音频。追问因为是动态生成的，可以先只显示文字；如果高自然度实时生成延迟可接受，再播放追问音频。

**禁止方案：**

| 方案 | 原因 |
|------|------|
| Browser Speech Synthesis | 听感机械，破坏真实面试氛围 |
| 低质量免费 TTS | 真实感不足，会降低产品质感 |
| 为了有声音而接入不自然音频 | 声音体验差时不如只展示文字 |

**每个 Agent 角色的声音应固定：**
- Sarah（HR）→ 女声，专业偏温和
- Marcus（HM）→ 男声，专业偏直接
- Alex（综合）→ 中性声

### 6.2 录音（P1，语音输入）

```javascript
// Push to Talk 核心逻辑
let mediaRecorder;
let audioChunks = [];

const startRecording = async () => {
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  mediaRecorder = new MediaRecorder(stream);
  mediaRecorder.ondataavailable = (e) => audioChunks.push(e.data);
  mediaRecorder.start();
};

const stopRecording = () => {
  mediaRecorder.stop();
  mediaRecorder.onstop = async () => {
    const audioBlob = new Blob(audioChunks, { type: 'audio/webm' });
    // 发送到 Whisper API
    const transcription = await transcribeAudio(audioBlob);
    // 直接提交，不需要确认
    await submitAnswer(transcription);
    audioChunks = [];
  };
};
```

### 6.3 页面路由

```
/session/[id]/call         → 来电动画页
/session/[id]/interview    → 面试会话页
/session/[id]/wrap         → 结束过渡页
```

### 6.4 会话状态管理

面试会话页的前端状态：

```typescript
type InterviewState = {
  currentChainIndex: number;      // 当前题目索引 0-2
  currentExchangeCount: number;   // 当前题目的追问次数
  phase: 'interviewer_speaking'   // 面试官在说话
        | 'user_answering'        // 用户在回答
        | 'ai_thinking'           // AI 在判断追问
        | 'ending';               // 结束流程
  exchanges: Exchange[];          // 当前题目的对话记录
  isRecording: boolean;           // 录音状态
}
```

## 7. 验收标准

### P0（文字输入模式，来电动画，结束过渡页）

**来电动画：**
- [ ] 面试官名字、角色、公司名（有时）正确显示
- [ ] 点击「Accept call」进入面试会话页
- [ ] 底部显示题型和预估时长

**面试会话（文字输入）：**
- [ ] 面试官问题正确显示，来自 Step 2 生成的 questions
- [ ] 题目进度 `Q1 of 3` 正确更新
- [ ] 文字输入 + Submit 正常工作
- [ ] 追问正确触发（基于 AI 判断）并显示
- [ ] 追问标注「Follow-up」小标签
- [ ] 退出按钮有确认弹窗
- [ ] 自然结束后跳转过渡页

**结束过渡页：**
- [ ] 进入后立即开始轮询 `/api/session/:id/feedback-status`
- [ ] `feedback_status=ready` 后显示「Open your feedback」按钮
- [ ] `feedback_status=failed` 后显示错误状态和重试按钮
- [ ] 点击「Open your feedback」跳转全局反馈页

### P1（用户语音输入 + 高自然度面试官语音）

- [ ] Push to Talk：按住录音，松开触发 Whisper 转写
- [ ] 转写结果短暂显示（1 秒）后直接提交
- [ ] 语音 / 文字模式可随时切换
- [ ] 面试官问题如果播放语音，必须是高自然度声音，可重听
- [ ] 不使用 Browser Speech Synthesis 或机械感 TTS

## 8. 设计禁止项

- 禁止在面试过程中显示计时器或倒计时（会增加焦虑）
- 禁止面试会话页有过多背景元素（保持聚焦）
- 禁止转写结果需要用户确认才能提交（破坏节奏）
- 禁止结束过渡页自动跳转到反馈页（用户需要主动「打开」）
- 禁止结束过渡页显示即时评分或分数（反馈还没到，不要提前剧透）
- 禁止来电动画可以跳过（它是仪式感的一部分，但可以设置 3 秒后自动可点击）
