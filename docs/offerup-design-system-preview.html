00 / Reference Layer

Simple first, then hierarchy, warmth, and refinement.

This layer is the judging standard for every token and component decision below.

01

Simplicity first

Remove unrelated decoration, extra containers, redundant copy, and visual noise. Minimal should feel edited, not unfinished.

02

Hierarchy serves information

Spacing, type, color, and component weight must clarify what matters first, second, and third.

03

Warm refinement

Warmth comes from paper, limewash ink, Lora, and soft accents. Refinement comes from alignment, thin lines, and restraint.

04

Atmosphere after structure

Texture and gradients may add craft only after the layout hierarchy is clear. Mood must never compete with content.

Reference Take Do not take
Current OfferUp landing Warm paper, limewash black, serif headline, calm CTA. Old score-first dashboard patterns.
Editorial AI sites Quiet confidence, typography-led beauty, off-white canvas. Floating gradient orbs, generic AI spectacle.
Workspace products Precise spacing, low visual noise, clear hierarchy. Cold monochrome sameness or generic productivity UI.
Editorial reports Reading rhythm, hairline dividers, strong section hierarchy. Decorative magazine layouts that weaken usability.

08 / Implementation Contract

Build from tokens, primitives, product modules, then pages.

This is the handoff layer for development. It prevents pages from inventing local styles.

File ownership

Each layer has a narrow job. Route pages compose; they do not create visual systems.

styles/tokens.css · all primitive, semantic, layout, state, motion, and density tokens
styles/globals.css · reset, body canvas, font smoothing, page background
components/ui · Button, Input, Textarea, Badge, Panel, Modal, Toast, Tooltip, ListRow, ReportBlock
components/layout · MarketingShell, AppShell, ReportShell
components/product · dashboard, setup, interview, feedback, answer-bank modules
routes/pages · data loading, ordering, page-specific composition

Component APIs

Props should describe product meaning, not raw visual values.

Buttonprimary · secondary · save · ghost · danger
Badgestrong · growing · developing · locked · role · drill · saved · risk
Panelsurface · quiet · report
ListRowdefault · selected · locked · disabled
Reportsignal · interviewer · next · risk

Build order

Create token and global style files first.
Map Tailwind to CSS variables, not raw hex values.
Build shared UI primitives and variants.
Build MarketingShell, AppShell, and ReportShell.
Build Dashboard and Setup product modules before page routes.
Build Interview, Feedback, Answer Bank, and polish modules.

Review gate

No raw hex values, ad hoc shadows, local radii, or local text scales in pages.
No page-local button, input, card, badge, or report variants.
Primary actions use ink; sage stays for save, success, and completion.
No nested cards, score-first dashboard, or analytics-style feedback UI.
Feedback preserves Answer signal → Interviewer heard → Next version.
Locked features use the shared locked state and never look like errors.
09 / Freeze Checklist

What is ready, what still needs a final decision.

Use this as the final design-system gate before production UI work starts.

Frozen decisions

✓Design phrase: refined editorial workspace.
✓Philosophy: simplicity, hierarchy, warm refinement, atmosphere after structure.
✓Palette: warm paper, limewash ink, sage, blue-gray, amber, clay red.
✓Primary actions use ink; sage is limited to save, success, and completion.
✓Typography direction: Lora + IBM Plex Sans with CJK and German fallbacks.
✓App density is compact by default, with page-level atmosphere only.

Still needs a call

?Font delivery: Google-hosted, self-hosted, or system fallback only.
?Developing status: amber-soft by default, clay-red-soft only for explicit concern.
?Tablet sidebar: keep labels until 768px, or collapse earlier into icon rail.
?Paper texture: CSS-only grid/grain, or a tiny generated texture asset.
