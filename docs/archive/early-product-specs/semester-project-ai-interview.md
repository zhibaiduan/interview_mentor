**一句话定位**：把你的真实经历，打磨成能在英语/德语面试中自信说出来的高质量回答。

## 2、市场分析：赛道里已经跑出来的产品在做什么，以及凭什么收费

**Exponent/Pramp**：课程 + 题库 + mock + 社区，走“内容生态型”。

[Interview prep for product, engineering, data science, and more - Exponent](https://www.tryexponent.com/home)

- 产品定位：面向科技求职者的一站式面试准备平台，核心是“内容生态 + 练习生态”。
- 解决问题：**用户不知道如何系统准备面试、练习路径分散、缺少持续反馈机制。
- 核心服务/模块：**课程（不同岗位）、题库、peer mock、AI mock、AI feedback、社区（Slack）、部分教练服务。
- Freemium + 订；公开页显示 Free 方案 $0/月，年付折算约 $12/月（页面同时展示“原月付价位 $79/月”），付费层解锁完整课程、无限 mock、AI 功能、社区等；另可加购 coaching。
- 正向评价集中在“体系化、路径清晰、练习频次高、社区有帮助”；负向反馈常见于“价格敏感”和“自动续费预期管理”（多见于第三方讨论）。

[**interviewing.io](http://interviewing.io/)：高保真技术面试实战平台，核心是“匿名真人 mock + 专家级反馈校准”。**

[Anonymous Coding & Technical Interview Prep for Software Engineers | interviewing.io](https://interviewing.io/)

- 产品定位是高价值实战型：强调接近真实大厂技术面的压力与反馈质量。
- 主要解决“缺少真实校准”问题：用户不知道自己在真实面试中的竞争水平。
- 核心模块包括匿名真人 mock（coding/system design/behavioral/ML）与详细反馈，另有 AI interviewer。
- 主要盈利方式是高客单价服务付费：围绕真人 mock 和高质量反馈收费。
- 定价通常不是低价订阅逻辑，更偏按场次/服务收费，整体价格门槛高于纯内容平台。
- 用户付费动机主要是“用最接近真实面试的方式快速发现短板并修正”。
- 正向评价集中在“反馈具体、实战感强、匿名降低心理压力”；负向反馈常见于“单次成本高、排期灵活度和覆盖面预期”。

---

**Yoodli：AI 表达与沟通教练平台，核心是“把表达质量做成可量化训练”。**

[AI Roleplay Platform for Communication Coaching | Yoodli](https://yoodli.ai/)

- 产品定位是表达教练型：重点优化语速、清晰度、停顿词和表达自然度。
- 主要解决“会做但说不好”问题：用户缺少低压力、可复练、可量化的表达反馈系统。
- 核心模块包括 roleplay、即时表达反馈、个人训练和企业训练能力。
- 主要盈利方式是 Freemium + 个人订阅 + 企业方案。
- 定价是免费层 + 付费层（支持月付/年付，年付有明显折扣），免费用户存在使用配额限制。
- 用户付费动机主要是“短周期看到表达改善，并能在面试中更自然专业地输出”。
- 正向评价集中在“即时反馈清晰、实操性强、信心提升明显”；负向反馈常见于“个别场景反馈稳定性与学习曲线”。

---

**Final Round AI：AI 面试助手平台，核心是“即时辅助 + mock + 求职工具链”。**

[Download Final Round AI Stealth App for Windows and Mac](https://www.finalroundai.com/download)

- 产品定位是即时帮助型：强调面试前后及面试过程中的实时支持体验。
- 主要解决“临场焦虑与准备不足”问题：用户希望快速获得提示和结构化辅助。
- 核心模块包括 mock interview、回答建议、简历/求职辅助及实时 copilot 类功能。
- 主要盈利方式是订阅制（按月/季/年打包能力）。
- 定价策略偏中高客单；公开退款规则对不同周期套餐有差异（如季/年首购短时退款窗口）。
- 用户付费动机主要是“在高压场景里获得即时安全感与提效感”。
- 正向评价集中在“上手快、短期提效明显”；负向反馈常见于“建议泛化、体验稳定性、价格与退款预期不一致”。

## 3、我们的切入点是什么，以及为什么这个地方值得切入

### 3.1 我们的切入点是什么

目前市场玩家的价值与定位区间大致是：

- **高保真实战型（[interviewing.io](http://interviewing.io/)）**：真人 mock + 高质量反馈；价值是“真实校准”，但价格较高。
- **内容生态型（Exponent/Pramp）**：课程+题库+mock+社区；价值是“系统化准备路径”。
- **通用 AI（ChatGPT/Claude/Gemini）**：好处：(a) 价格非常便宜 问题：(a) 非常考验个体的 prompt 能力，决定了能否得到专业的输出 (b) 缺乏整个训练过程的追踪和成长曲线
- **表达教练型（Yoodli）**：语速/清晰度/停顿词反馈；价值是“表达可量化”，但岗位竞争力深度有限。
- **即时辅助型（Final Round AI）**：实时帮助与提效；价值是“临场安全感”，但口碑分化较明显。

但在这些定位之间，还有一个没有被充分满足的空白：**面向 non-native 科技候选人的岗位化专业外语面试表达训练**。

我们选择 non-native speaker 科技候选人，不是因为这是一个泛泛的“外语不够好”的人群，而是因为他们处在一个高压力、高回报、强结果导向的场景里：一次面试表现会直接影响 offer、薪资、签证、职业起点和长期发展。他们通常已经具备真实项目经验和基础技术能力，但在英语或德语等专业外语面试中无法稳定地把能力表达出来。也就是说，他们的问题不是“不会”，而是“说出来以后不像会”。

这类用户不会天然选择我们。他们现有的替代方案主要有四类，但每一类都只能解决一部分问题：

- **通用 AI（ChatGPT/Claude/Gemini）**可以生成回答和润色表达，但效果高度依赖用户会不会提问、会不会判断输出质量。对于表达不自信的用户来说，通用 AI 经常给出“看起来正确、但不一定像本人、也不一定适合该岗位”的答案，并且缺少持续训练记录、前后对比和可见进步。
- **内容/题库/课程平台（Exponent/Pramp）**可以提供系统准备路径，但更偏“学什么、练什么”，不一定能针对用户自己的简历、项目经历、目标岗位和当下回答进行逐句打磨。
- **真人 mock、AI mock 或高保真模拟面试平台（interviewing.io 等）**反馈质量高，但成本高、频次低、心理压力大，不适合用户每天反复练同一道题、持续修正表达。更重要的是，这类工具通常默认用户已经具备足够的专业外语表达能力，反馈重点放在面试内容、答题结构和综合表现上，而不会把“语言表达能力本身”作为需要被诊断、训练和逐步提高的核心对象。
- **表达教练工具（Yoodli 等）**可以量化语速、停顿、清晰度，但它更关注“说得是否流畅”，不一定判断“这个回答是否体现岗位竞争力、是否打中了面试官真正关心的点”。

因此，这群人的真正核心痛点不是单纯的外语表达，也不是单纯的面试技巧，而是两者叠加后的“职业表达转化问题”。他们需要的也不是一次性的答案生成或面试模拟，而是更长周期、更低压力、更低成本的持续训练：在反复练习中提升外语表达的自信度、流利度和熟练度，同时把每一道回答打磨到清晰、专业、能够展示自己的程度。

1. **他们不知道自己的回答为什么听起来不够强。** 他们可能有项目、有技能、有经历，但回答缺少结构、重点和岗位语言，导致面试官听不到能力信号。
2. **他们不知道如何把反馈变成下一版更好的回答。** 通用建议如“更具体一点”“更自然一点”“多体现 impact”并不足够，他们需要可直接复练的改写版本和修改理由。
3. **他们缺少安全、低成本、高频率的练习闭环。** 真正的提升来自多次重录和比较，尤其是语言表达熟练度需要更长时间训练；但现有方案要么太贵、要么太泛、要么没有沉淀。
4. **他们需要答案像自己，而不是像模板。** 这类用户最怕两种结果：一是表达不专业，二是被 AI 改得过度精致、失去真实性。真正有价值的是把他们自己的经历变得更清晰、更职业、更有说服力。

我们要满足的不是“给用户更多题目”，而是帮助用户完成从原始经历到可上场回答的转化：

**简历/JD/项目经历 -> 个性化问题 -> 语音作答 -> 表达层反馈 + 竞争力层反馈 -> 可执行改写 -> 同题重录 -> 前后对比 -> 个人题库沉淀。**

他们愿意付费的概率取决于我们能否让 ROI 变得足够清晰。最能打动他们付费的不是功能数量，而是三种证据：

1. **结果证据：** 用户能明显看到同一道题从第一版到第二版变强，回答更清楚、更有结构、更贴近岗位要求。
2. **效率证据：** 用户感到这比自己反复问通用 AI 更省时间，比真人 mock 更便宜、更可持续。
3. **能力资产证据：** 用户积累的不只是一次答案，而是一套可复用的个人表达库、项目故事库和岗位化回答框架。

所以，我们的市场切入点不是“AI 面试练习”这个大类，而是 non-native 科技候选人在真实求职周期中最愿意为结果付费的窄场景：**把自己的经历打磨成清晰、自然、专业、岗位匹配、可重复上场的英语/德语面试回答。**

### 3.2 为什么这个地方值得切入

这个切入点值得做，是因为它站在“国际学生 / 跨国求职者 / 早期科技候选人”的交叉处，人群不小，而且需求强。对这些用户来说，专业外语面试不是兴趣学习，而是直接影响 offer、薪资、签证、职业起点和身份安全感的关键场景。他们已经有项目经历和基础能力，但需要一边准备面试，一边提升英语/德语等专业外语表达能力和面试技巧，因此比 native speaker 更需要低压力、低成本、可持续的训练。

这类用户有付费可能，但价格和价值定位要放在正确的位置：不能像真人 mock 那样高价低频，也不能只是通用 AI 的包装。我们更适合做中间层：比真人 mock 更便宜、更高频，比通用 AI 更岗位化、更可追踪。我们提供的不是“更多题目”，而是把用户自己的经历打磨成可上场的专业外语面试回答，并逐步沉淀成可复用的职业表达资产。此外，这部分用户进入职场之后，往往还有下一阶段需求：继续提高 professional language expression，并针对汇报、会议、协作沟通等真实工作场景进行刻意练习。

## ⭐ 4、产品定位：我们为谁解决什么问题，以及如何创造价值

### **⭐ 4.1 目标用户、核心痛点与核心需求**

Target users / pain points / concerns（可演示版）：

![Target Users, Core Pain Points, and Concerns](/Users/miumiu/.codex/generated_images/019df38f-1f30-7cc0-b840-6aa9084a778b/ig_097585ee7cd266b10169f8ff71faf08191aab4989b6ca52581.png)

我们的目标用户是 **0-5 年经验、正在申请初级/中级科技岗位、需要用英语或德语面试的 non-native 求职者**。他们通常已经有真实项目经历和基础专业能力，但专业外语表达还没有到得心应手的程度：知道自己做过什么，却不能稳定地用外语讲清楚、讲专业、讲出亮点。

他们的核心痛点不是“缺少更多面试题”，而是：在真实面试压力下，无法自信、流利、专业地用外语展示自己的能力。很多 non-native 求职者以为自己“能说”，但实际听起来容易像背题、背模板，缺少专业用语和面试回答结构；更难的是，他们自己往往不容易意识到这些问题。具体来说，他们需要同时解决三件事：

1. **表达问题**：回答听起来不够自然、不够清晰，容易有模板感、翻译感，缺少真实职业人的表达方式。
2. **面试问题**：回答结构不够强，不能很好地对齐岗位要求和面试官评估标准。
3. **训练问题**：语言表达熟练度需要更长时间训练，但真人 mock 成本高、频次低，通用 AI 又太依赖用户自己会不会提问和判断输出质量。

更关键的是，这类用户常常缺少一个外部视角来意识到问题。他们以为自己已经把经历说清楚了，但面试官实际听到的可能只是一些零散信息，听不到 ownership、technical decision-making、impact 或岗位匹配度。产品需要帮助用户看见这个差距：**“我以为我表达出来了” vs “招聘者实际听到了什么”**。因此，反馈不能只是告诉用户“更具体一点”，而是要通过招聘者听感、岗位要求对照、模板感/翻译感提示、原始回答与 polished answer 对比，让用户意识到自己的能力信号在哪里丢失，并知道下一版应该怎么改。

因此，他们真正需要的是一个低压力、可持续、针对个人经历和目标岗位的训练闭环：一边准备面试，一边提升专业外语表达能力和面试技巧，把自己的项目经历打磨成可上场、像自己、岗位匹配的回答。

### **4.2 长远愿景（Vision）**

我们希望从“专业外语面试输出训练”切入，逐步发展为 non-native 专业人士的工作场景外语表达训练平台。

长期目标不是做大而全题库，而是有目的地提升用户在关键职业场景中的专业外语表达竞争力。用户在入职之后，仍然需要在英语或德语等非母语环境中完成汇报、协作沟通、会议表达、绩效沟通和晋升表达；因此，我们可以从面试场景开始，逐步扩展到更长期的职场外语训练。

### **⭐ 4.3 MVP 阶段目标（MVP Goal）**

MVP 第一阶段不验证“我们能不能做一个完整的 AI 面试平台”，而是验证一个更窄、更关键的命题：

**non-native 科技求职者是否愿意为“基于自己简历/JD/项目经历的专业外语面试回答打磨”持续使用并付费。**

对 semester project 来说，六月份的阶段目标更具体：先做出一个功能可用的 MVP 版本，支持我们把 demo 发出去，并招募一批种子用户试用。

第一阶段要验证的不是题库规模，也不是模拟面试完整度，而是用户是否能在一次短训练中明确感受到：自己的回答从“不清楚、不自信、不专业”变成了“更清晰、更自然、更岗位匹配”。如果用户愿意根据反馈重录同一道题，并开始沉淀自己的个人回答库，说明这个方向有继续做深的价值。

MVP 要做的范围包括三个核心模块：

1. **模拟面试模块**
    
    用户提供简历、JD 和目标公司信息后，系统聚焦于项目经历、职业经历、行为面试和 HR motivation 类问题，进行岗位化模拟面试。它不是通用 mock interview，而是尽量模拟“这个公司、这个岗位、这个招聘角色”会怎么问。
    
2. **反馈与回答打磨模块**
    
    反馈分为整体反馈和单题反馈。无论是整体反馈还是单题反馈，都同时提供 **recruiter 视角** 和 **coach 视角**。
    
    - **Recruiter 视角**：解释对方为什么会问这个问题、实际想考察什么；从招聘者听感出发，判断回答是否清晰、可信、岗位匹配；并说明这个回答和其他候选人相比可能处在什么位置。
    - **Coach 视角**：辅导用户如何表达得更自然、更讨喜、更结构化，让面试官更容易理解用户的专业能力、项目价值和个人素质。
    
    对单题回答，系统还需要提供 polish / rewrite 能力，把用户原始回答打磨成更自然、更符合本人经历、更适合真实面试使用的高标准版本。
    
3. **Question Bank 模块**
    
    支持用户沉淀自己的个人面试题库，以及已经 polish 好、可以随时复习和复用的回答语料库。这个模块不是公共题库，而是基于用户自己的简历、项目经历、目标岗位和过往训练结果形成的个人资产。

MVP 的核心体验指标也对应这三个模块：

1. **问题是否足够定制化**
    
    系统是否真的基于 JD、目标公司信息和用户简历提出有价值的问题，而不是泛泛的通用题。用户应该能感觉到：这些问题像是这个岗位、这个公司、这个招聘角色真的会问的问题。在追问过程中，用户也应该觉得追问是有效的，能够推动他把项目经历、职业经历和动机讲得更清楚。
    
2. **反馈是否足够有帮助**
    
    反馈不能只是“回答不错，但可以更具体”这种通用评价，而是要打开用户的视角：对方为什么问这个问题、实际想考察什么、自己的回答在招聘者听起来是什么感受、哪里没有讲清楚、哪里没有体现竞争力。同时，反馈要给出具体可执行的行动建议，让用户知道下一版应该怎么改。
    
3. **回答改写是否真的提升回答质量**
    
    Polish / rewrite 不是把用户回答改成标准模板，而是在用户原始回答的基础上进行润色和调整，让回答仍然像他本人会说的话，同时更符合岗位要求、更清晰、更结构化、更突出价值，也更有竞争力。

MVP 暂时不做的范围，要围绕“工具”而不是“平台”来收窄。第一阶段不是做一个完整面试平台，而是做一个成本更友好、可反复使用的岗位化回答打磨工具：

1. **不做 live 模拟面试**：不做实时视频/语音对话式 mock interview，而是采用异步作答、转写、反馈和 polish 的方式，降低使用成本和实现成本。
2. **不做完整面试流程管理**：不覆盖从 HR screen 到 technical round、case study、final round 的全流程，而是先聚焦项目经历、职业经历、行为面试和 HR motivation 这几类最依赖表达质量的问题。
3. **不做技术能力评测**：不做 coding test、算法题评测、系统设计评测或 case study 自动判分，避免把产品重心从“专业外语表达和回答打磨”转移到硬技能评估。
4. **不做公共题库和课程内容**：不做大而全题库、课程体系、语法课或语言学习计划，只保留基于用户简历、JD 和目标公司的个性化问题生成。
5. **不做社交和真人服务**：不做社区、peer mock、真人教练匹配或人工批改，优先验证 AI 工具本身是否能提供足够有用的反馈和回答打磨。
6. **不做多模态表现分析**：暂时不做视频、表情、肢体语言、眼神和语音情绪分析，先聚焦回答内容、表达自然度、结构和岗位匹配度。
7. **不做复杂求职工具链**：暂时不做简历生成、cover letter、职位追踪、申请管理等外围功能，避免稀释“面试回答打磨”这个核心价值。

一句话总结：**对于 semester project 六月份 presentation 这个节点，我们的目标是完成一个可真实跑动的 MVP 版本，并且能够支持后续招募种子用户。**

Demo 发布后的种子用户验证，可以看一个简单漏斗：

1. **招募转化**：demo 发出去后，能招募到多少目标种子用户愿意试用。
2. **完整体验转化**：有多少种子用户能够完成一次模拟面试流程，并真正看到反馈页面。
3. **重复使用转化**：有多少用户会回来进行第二次、第三次模拟面试。
4. **资产沉淀转化**：有多少用户会保存问题、保存 polished answer，并开始沉淀自己的 Question Bank。

## ⭐ 5、路线图：六月二十号 presentation 前要完成什么

### 5.1 六月二十号节点目标

到 **2026 年 6 月 20 日 presentation**，我们的目标不是完成一个成熟商业化产品，而是完成一个**可真实跑动、体验过关、能够支持后续招募种子用户的 MVP 版本**。

这个版本至少要能跑通一条核心路径：

**用户输入简历 + JD + 目标公司信息 -> 系统生成岗位化问题 -> 用户完成异步作答 -> 系统生成 recruiter + coach 双视角反馈 -> 用户获得 polished answer -> 用户保存到 Question Bank。**

### ⭐ 5.2 MVP 阶段的重点和难点

从技术架构角度看，MVP 的难点不是“把页面做出来”，而是让 AI 输出稳定达到我们定义的核心体验：问题足够定制化、反馈足够有帮助、回答改写真的提升质量。因此需要重点探索以下几个方向。

**1. 岗位/公司/简历理解链路**

问题定制化取决于系统能否正确理解三类输入：JD、目标公司信息、用户简历。这里的难点是信息来源杂、结构不稳定、简历里有大量个人化项目细节。

需要探索的技术方案：

- **结构化解析**：把 JD、简历、项目经历抽取成结构化字段，例如岗位要求、核心技能、项目职责、impact、疑点和可追问点。
- **公司/岗位信息补充**：MVP 可以先让用户输入公司官网或产品信息，也可以探索轻量 web search / crawl 方案，抓取公司产品、业务方向和岗位背景。LinkedIn 信息如果涉及登录或抓取限制，MVP 阶段应谨慎处理，优先使用用户提供的信息和公开网页。
- **岗位匹配分析**：先生成一份“candidate-job fit map”，标出简历里哪些经历最匹配 JD，哪些地方可能被追问，再基于这份 map 生成问题。

推荐 MVP 方案：先不要做复杂 agent。采用 **固定 workflow + structured output**：解析 JD/简历 -> 生成 fit map -> 生成 5-8 个高相关问题 -> 用户选择或系统逐题推进。

**2. Prompt / skill / workflow 的稳定性**

如果只是一个大 prompt 直接生成问题、反馈和 polish，输出很容易泛化。MVP 需要把任务拆开，让每一步有明确输入、输出和质量标准。

需要探索的技术方案：

- **Prompt 模板分层**：分别设计 company/JD analysis、resume analysis、question generation、answer evaluation、answer polish 几类 prompt。
- **双视角反馈结构**：recruiter 视角负责判断“听起来如何、是否匹配岗位、和其他候选人相比弱在哪里”；coach 视角负责给出“下一版怎么表达更自然、更结构化、更有说服力”。
- **输出格式约束**：用 JSON schema 或固定 markdown schema 约束模型输出，保证前端能稳定渲染。
- **质量评估样例集**：准备 5-10 组简历/JD/回答样例，用来反复测试问题是否定制化、反馈是否具体、polish 是否像本人。
- **Agent 框架评估**：CrewAI、LangChain / LangGraph、LlamaIndex 可以调研，但 MVP 不一定需要引入。除非我们确实需要多步骤状态管理、工具调用或检索，否则固定 workflow 更可控、更快交付。

推荐 MVP 方案：优先做 **deterministic workflow + prompt library + eval examples**，不要一开始上复杂 multi-agent。

**3. 异步模拟面试的产品与技术形态**

我们不做 live 模拟面试，所以核心问题是：如何让异步工具仍然有“被追问、被理解、被辅导”的感觉。

需要探索的技术方案：

- **一次模拟面试的长度和题量**：不能让用户完成一场很长的完整面试，但也要保留一点面试沉浸感。MVP 可以先设计成 **5-10 分钟的小型模拟面试 session**，围绕 3-5 个高相关问题展开，必要时加入 1-2 个轻量追问。
- **语音链路采用哪种方案**：产品核心是训练专业外语口语表达，所以用户作答必须以“说”为主。需要确定的是采用“录音 -> speech-to-text 转写 -> 文本理解/反馈 -> 文本输出/可选 text-to-speech 播放”的异步链路，还是采用实时语音流。MVP 更可能先采用异步语音转写链路，以控制成本和实现复杂度。
- **状态管理**：每次 session 需要保存 JD、简历摘要、问题列表、用户回答、反馈、polished answer、Question Bank 归档状态。
- **反馈页生成时机**：用户完成 5-10 分钟的小型模拟面试后，统一进入反馈页。反馈页同时提供整体反馈和单题反馈，避免用户刚答一题就被打断，也避免完整长面试导致反馈等待过久。

推荐 MVP 方案：异步语音、小型 session 闭环优先。先把“3-5 个岗位化问题 -> 5-10 分钟语音作答 -> 转写 -> 整体 + 单题反馈 -> polished answer -> 保存”的体验打磨好，再评估是否需要实时语音流。

**4. 成本控制与可扩展试用**

种子用户阶段需要支持免费或低成本试用。如果每一次完整体验都调用多次高价模型，后续招募会受限。

需要探索的技术方案：

- **模型分层**：轻量模型做摘要、分类、格式化；高质量模型用于问题生成、反馈和 polish。
- **缓存策略**：同一个 JD / 公司分析结果可以缓存；同一个用户简历解析结果可以复用。
- **额度控制**：每个种子用户限制 session 数、题目数、polish 次数。
- **异步任务队列**：反馈和 polish 可以异步生成，避免用户等待太久，也便于失败重试。
- **日志与成本监控**：记录每次 session 的 token、模型调用次数、失败率和平均成本。

推荐 MVP 方案：先用最少模型调用跑通体验，再根据真实测试数据决定是否需要更复杂的模型路由和队列。

**5. 数据隐私、GDPR 与 AI Act 边界**

这个产品会处理简历、项目经历、面试回答、语音/转写文本和目标岗位信息，天然涉及个人数据。尤其如果面向德国或欧洲用户，隐私设计不能等到最后再补。

需要探索的技术方案：

- **数据最小化**：只收集完成训练所必需的信息；不要求用户上传不必要的身份证明、联系方式或敏感信息。
- **保存策略**：明确哪些数据临时保存，哪些进入 Question Bank，哪些可以一键删除。
- **第三方模型数据政策**：确认 API provider 是否默认用于训练、数据是否出境、是否支持关闭训练和企业级数据保护。
- **用户控制权**：提供删除简历、删除回答、删除 Question Bank 的基础能力。
- **AI Act 风险边界**：产品应定位为候选人侧 coaching tool，不作为雇主侧招聘筛选或自动决策工具，避免被表达成“自动判断候选人是否合格”。

推荐 MVP 方案：实现最小隐私承诺：用户知道上传什么、为什么上传、保存多久、如何删除；presentation 中说明后续 GDPR / AI Act 合规计划。

**6. Demo 稳定性和可展示性**

Presentation 前必须确保 demo 不只是“功能存在”，而是稳定展示核心价值。

需要探索的技术方案：

- 准备 1-2 套稳定 demo case，包括简历、JD、公司信息、用户回答和预期输出。
- 关键 AI 输出最好支持 fallback：如果现场 API 不稳定，可以展示提前生成的 sample result。
- 反馈页要优先做好信息架构，让 recruiter 视角、coach 视角、polished answer 和保存入口非常清楚。
- 埋点至少覆盖：开始 session、完成作答、到达反馈页、点击 polish、保存到 Question Bank、二次登录。

推荐 MVP 方案：真实功能 + 稳定 demo case 双保险。presentation 展示真实跑动能力，同时避免现场不确定性影响核心叙事。

### ⭐ 5.3 建议分工

团队有三个人，建议不要简单按“前端 / 后端 / prompt”切开，而是拆成三个都有明确价值、难点和展示产出的模块。这样每个人都能对一个完整问题负责，也能在 presentation 里讲清楚自己的贡献。

**模块 A：产品体验与用户验证负责人（Product / UX / Validation）**

这个模块的价值是确保我们做出来的不是一堆 AI 功能，而是一个目标用户真的能理解、愿意试用、能感受到帮助的工具。

重点负责：

- 定义核心用户流程：输入简历/JD/公司信息 -> 语音模拟面试 -> 反馈页 -> polish -> Question Bank。
- 设计反馈页的信息架构，让 recruiter 视角、coach 视角和 polished answer 清楚可读。
- 设计种子用户验证漏斗：招募转化、完整体验转化、二次/三次使用、Question Bank 保存。
- 准备 demo case、presentation story 和种子用户招募材料。

重点难点：

- 如何让第一次使用在 5-10 分钟内让用户感到“这个反馈真的有用”。
- 如何把复杂 AI 输出组织成用户能理解、愿意继续练的页面。
- 如何把 semester project 的 presentation 讲成一个完整产品故事，而不是技术 demo。

**模块 B：AI 体验质量负责人（AI Workflow / Prompt / Evaluation）**

这个模块的价值是确保 MVP 最核心的智能体验足够好：问题不是通用题，反馈不是泛泛评价，polish 不是模板答案。

重点负责：

- 设计 JD / 公司 / 简历理解流程，生成 candidate-job fit map。
- 设计问题生成、轻量追问、双视角反馈、polish / rewrite 的 prompt 或 skills。
- 调研是否需要 CrewAI、LangChain / LangGraph、LlamaIndex 等 workflow / agent 方案；如果不引入，也要设计清楚固定 workflow。
- 建立 5-10 组评估样例，用来测试问题定制化、反馈有用性和回答改写质量。

重点难点：

- 如何让 AI 真的“读懂这个岗位和这份简历”，而不是输出看似合理的通用内容。
- 如何保证输出稳定、结构化、可渲染，而不是每次格式都变。
- 如何在保留用户本人表达风格的前提下，把回答改得更清晰、更有竞争力。

**模块 C：工程架构、数据与成本负责人（Engineering / Data / Cost / Privacy）**

这个模块的价值是让 demo 真实可跑、成本可控、数据可保存，并且为后续种子用户测试留下基础设施。

重点负责：

- 实现异步语音作答链路：录音、speech-to-text、文本处理、反馈生成、polish 保存。
- 设计 session 数据结构：用户输入、问题列表、回答、反馈、polished answer、Question Bank。
- 负责模型 API 集成、调用次数控制、缓存策略、错误 fallback 和基础 analytics。
- 调研 GDPR / AI Act / 数据主权相关风险，给出 MVP 最小隐私设计。

重点难点：

- 如何让 5-10 分钟的小型模拟面试稳定跑通。
- 如何控制每次试用的模型调用成本，让种子用户测试可持续。
- 如何处理简历、语音、回答这类个人数据，避免从 MVP 阶段就形成高风险数据架构。

### ⭐ 5.4 暂定里程碑

1. **Milestone 1：产品界面与概念验证（5 月中旬）**
    
    到五月中旬，产品应该已经有比较清晰的前端页面和核心体验雏形，让人能看出来这个产品长什么样、用户会怎么使用。这个阶段重点是确定用户旅程、核心页面、反馈页结构和 Question Bank 的呈现方式。界面和概念相对清晰之后，就可以开始在社交平台发布概念/招募信息，收集目标用户的基础痛点，验证我们对用户需求的假设是否合理。
    
2. **Milestone 2：End-to-end demo 跑通（5 月底）**
    
    到五月底，应该有一个基本能够完整跑一遍的 demo：输入简历/JD/公司信息 -> 语音模拟面试 -> 转写 -> 反馈 -> polish -> 保存到 Question Bank。这个版本不需要体验完美，但必须能完整展示核心流程。
    
3. **Milestone 3：核心体验打磨与差异化验证（6 月上旬）**
    
    六月上旬重点打磨 MVP 的核心体验：问题是否足够定制化，反馈是否足够有帮助，回答改写是否真的提升质量。这个阶段要持续调 prompt / workflow / skills，并用真实或半真实 case 做测试，让输出质量达到有区分度、有竞争力、能够带来用户留存的水平。同时继续通过社交平台和招募表单预热种子用户。
    
4. **Milestone 4：Presentation（6 月 20 日）**
    
    六月二十号展示一个可真实跑动、体验过关、差异点清晰的 MVP。Presentation 需要说明产品为什么不是另一个普通面试工具，而是一个面向 non-native 科技求职者的岗位化专业外语回答打磨工具，并展示它如何支持后续招募种子用户和验证核心体验。

### ⭐ 5.5 Presentation 需要证明什么

Presentation 的核心叙事不是“我们也做了一个 AI 面试产品”，而是要完成一个预期反转：

**用户一开始以为这只是另一个 mock interview / ChatGPT wrapper，但看完 demo 之后意识到：它其实是在帮 non-native 科技求职者把自己的真实经历，打磨成可以在目标岗位面试中自然、专业、有竞争力地说出来的回答。**

这条叙事可以按五步来讲：

1. **先指出普通 AI 面试工具的问题**
    
    大多数 AI 面试产品会生成一组看起来合理的问题，也能给一些反馈；但它们往往有三个问题：问题不够基于具体岗位和简历，反馈不够像真实招聘者视角，回答改写容易变成模板答案。对 non-native 求职者来说，这还不够，因为他们真正需要的是把自己的经历用专业外语讲清楚、讲自然、讲出竞争力。
    
2. **展示我们的切入点：不是练“更多题”，而是打磨“可上场回答”**
    
    我们不是做大而全题库，也不是做 live mock 平台，而是做一个异步、低成本、可反复使用的回答打磨工具。它从简历、JD、目标公司出发，帮助用户完成一条闭环：岗位化问题 -> 语音作答 -> 双视角反馈 -> polished answer -> Question Bank。
    
3. **Demo 第一击：问题不是通用题，而是基于岗位和简历生成的**
    
    最好用一份具体 JD 和一份具体简历现场展示：系统为什么会问这些问题，这些问题和岗位要求、候选人项目经历之间有什么关系。听众需要感觉到：这个问题不是 ChatGPT 随便生成的，而是像招聘者真的读过这份简历之后会问的。
    
4. **Demo 第二击：反馈不是泛泛评价，而是打开了招聘者视角**
    
    反馈页要清楚展示 recruiter 视角和 coach 视角。recruiter 视角解释“这个问题在考察什么、回答听起来怎样、哪里没有体现竞争力”；coach 视角告诉用户“下一版具体怎么改”。这会让产品区别于普通语法纠错或通用面试建议。
    
5. **Demo 第三击：Polish 不是模板化改写，而是把用户自己的回答变得更强**
    
    Demo 里应该展示原始回答和 polished answer 的对比：原始回答可能真实但松散，polished answer 仍然像用户本人，但更清晰、更结构化、更符合岗位要求、更能突出项目价值。

最后可以补充展示 Question Bank：用户不是只得到一次反馈，而是在沉淀自己的个人面试语料库。这一点能让听众理解长期价值：它不只是一次模拟面试，而是一个专业外语面试表达资产的积累工具。

Presentation 最后要让听众记住一句话：

**这不是另一个 AI 面试官，而是一个面向 non-native 科技求职者的专业外语回答打磨工具。它的价值不在于问更多题，而在于让用户把自己的真实经历讲得更清楚、更自然、更岗位匹配，并且逐步沉淀成自己的职业表达资产。**

## ⭐ 6、产品 UI / UX 风格

产品的 UI / UX 应该传递 **专业、可信、低焦虑** 的感觉。我们的用户本身正在准备面试，容易紧张和自我怀疑，所以界面不应该制造强烈的考试感、评判感或压迫感，而应该像一个安静、可信赖的 career coach workspace：简洁、克制、有专业感，同时保留温度，让用户觉得这里是可以安全练习、被具体指导、逐步变好的地方。

视觉上应当明亮、干净、留白充足，使用稳定、柔和、不过度刺激的色彩系统。体验重点放在反馈页和前后对比：用户需要清楚看到 recruiter 视角、coach 视角、原始回答和 polished answer 的差距，从“我不知道自己哪里不好”进入到“我知道下一步怎么变好”。如果界面能让用户感觉“它真的读懂了我的经历和目标岗位，并且把我的回答改得更像一个专业的我”，这个产品就会比普通 AI 面试工具更有记忆点。
